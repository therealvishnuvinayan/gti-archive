## Source conflicts and V2 precedence

- Source project relationships are not new business roles. The five V2 roles and separate Technical Administration remain authoritative. No general Collaborator role, vendor user or fictitious Director membership is added.
- Source allows Director as a junior’s mandatory Co-owner. V2 requires an eligible SPM Co-owner and Director approval for every JPM creation.
- SPM drafts and creation from a Director-approved executable version use current V2 permissions. Source Director-only master-template editing is not authority to designate an SPM draft as an official standard.
- Source Owner/Co-owner overrides, approved skips and leave deputies do not create V2 bypasses. Existing gates and independent runtime approval rules remain intact.
- Initial and Final Concept source stages become manually created Universal Tasks. A reviewed creative evidence upload is not proof of task status, concept count, revision count or mandatory linkage.
- Source Purchase → CEO → all Executors → Director cannot be represented by the supported role registry. The candidate’s internal Director review is explicitly narrower, never labelled a complete external artwork-release chain.
- Source Product Card Owner-only review is representable, but existing V2 independence means the Owner must not supply that stage’s evidence. Synthetic JPM contributions, SPM file/Owner review and separate Director toolkit review demonstrate an eligible arrangement; a real project must plan independent contributors.
- Source automatic project closing, vendor ratings and archiving do not supersede the V2 Owner request, explicit Director document policy and Director final decision. External contractual checks at artwork acceptance remain unsupported; final-project document policy cannot substitute for them.
- Unlimited attachments and automatic previews cannot override bounded current storage/file contracts. Existing file review and shared identity remain authoritative.

## Packaging interpretation

Six Stage Builder stages cover Brief, Research, Final Artwork Specification, Production/Handover Evidence, Implementation/Supervision and Commercialisation Preparation. Initial and Final creative development are Universal Tasker instructions. Every stage/block/field/checklist/approval/gate has paragraph traceability in `packagingBlueprint().trace`. Existing Stage Builder v1 parsing and validation are used; unsupported official requirements are returned by `validateBlueprint(blueprint, "OFFICIAL_STANDARD")`. The separately bounded `INTERNAL_EVIDENCE_PILOT` can be tested using genuine approvals, without claiming those omitted requirements are satisfied.

Candidate requiredness and file allowlists/counts are proposed authoring choices, not facts asserted by the source. Text fields record references, summaries and omission reasons; they do not enforce row-level applicability. The attached per-file/market/unit registers preserve detailed source content for human review. The default toolkit note is guidance and a human-check item; no Director-only modification control inside an uploaded document is claimed. No actual official workflow is published, activated or designated by this implementation.
